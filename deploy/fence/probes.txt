# The fence probes, in ONE file. deploy/fence-check.sh runs them from inside each Bulig property set (worker, kernel, build, cli-worker,
# cli-kernel) and fence-probe.py judges them. Columns:   expect   sets   name   kind   target
#
# expect  deny        must FAIL to connect (any error). If the target is not listening even without the fence the result is "inconclusive".
#         allow       must succeed.
#         allow-late  must succeed, but only a warning if it does not (the kernel may not be up yet).
#         known       a documented limit: reported, never fails.
# sets    comma list of: worker kernel build cli-worker cli-kernel
# kind    tcp host:port | [v6]:port | unix path | abstract name (leading NUL added) | dns hostname | https hostname | http url
#         | pwd (getpwuid of the running uid) | socketpair (AF_UNIX socketpair, what node child_process uses) | spawn (run a child)
#         | node (run `node -e <target>`; works when it exits 0) | exec (run the command in <target>; works when it exits 0)
# The build's user-lookup is a KNOWN limit: it runs as a DynamicUser, which has no /etc/passwd entry, and libnss_systemd resolves dynamic users
# only over the varlink socket /run/systemd/userdb/io.systemd.DynamicUser, which needs AF_UNIX, which the build does not have (on purpose).
# The build does not need the lookup (HOME is set explicitly; node's os.homedir() reads $HOME), and node-homedir proves that.
# placeholders: @HOST@ = each of this machine's own public addresses, @TAILSCALE4@ = this machine's own tailscale address.
# The targets are what ths-prod-01 had on 19 Oct 2026. A target that is not there any more shows as inconclusive, not as a pass.
